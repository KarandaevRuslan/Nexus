# Collatz + n+1: bounded directed graph (Nexus v0.1.18 Refactor v2)

## Что именно строим

В отличие от исходной задачи Коллатца, здесь число `n` порождает **два типа рёбер**:

- `n → n / 2`, если `n` чётно, иначе `n → 3n + 1`; **включая переход `1 → 4`**. В графе вершина `1` не терминальна, в отличие от классического перечисления одной цепочки Коллатца.
- `n → n + 1` **для каждого впервые найденного числа**, включая `1`.

Обнаруженные повторно числа **не добавляются второй раз**, но рёбра к ним сохраняются. Это **ориентированный граф**, а не дерево (возможны слияния и циклы). Простым считается число `p ≥ 2` с ровно двумя положительными делителями; мы считаем **простые вершины**, не простые рёбра и не кратность посещений.

Граф математически бесконечен из-за переходов `n → n + 1`. Параметр `maxVertices` означает **строгий предел на количество разных вершин**. Когда этот предел достигнут, мы не добавляем неизвестные числа и пропускаем направленные к ним переходы, увеличивая `omittedTransitions`. Однако все уже известные вершины обрабатываются, а связи с уже известными вершинами сохраняются. Поэтому после завершения `vertexCount ≤ maxVertices`, `processed === vertexCount` и все рёбра ссылаются на включённые вершины. При любом конечном лимите результат неизбежно **усечён**.

### Порядок, влияющий на состав графа

Очередь обходится в ширину (FIFO), при открытии вершины сначала рассматривается **Collatz-переход**, потом **`n + 1`**. Порядок нужен, чтобы при ограничении размера результаты были детерминированными; иной порядок может дать другие вершины и другой `primeCount`.

## Вызов и возвращаемые данные

```ts
import {
  collatzGraph,
  createCollatzGraphExplorer,
  collatzGraphToDot,
} from "./examples/collatz-graph";

const graph = collatzGraph(6, 10);
console.log(graph.vertexCount);        // 10
console.log(graph.edgeCount);          // 14
console.log(graph.primeCount);         // 5
console.log(graph.omittedTransitions); // 6
console.log(graph.vertices);           // bigint[]
console.log(graph.edges);              // { from: bigint, to: bigint, kind: ... }[]
console.log(collatzGraphToDot(graph)); // Graphviz DOT directed graph
```

`graph.vertices` содержит `[6n, 3n, 7n, 10n, 4n, 22n, 8n, 5n, 11n, 2n]`. Простые вершины: `2, 3, 5, 7, 11`. Результат содержит **14 направленных рёбер**, 6 потенциальных дуг на ещё не включённые числа отклонено из-за лимита.

Повторное использование одного Dispatcher и одного Handler:

```ts
const explorer = createCollatzGraphExplorer(100); // бюджет на максимальный размер
try {
  const first = explorer.explore(6, 10);
  const second = explorer.explore(7, 20);
  const third = explorer.explore(6, 10);
  // first и third идентичны по содержимому; second не влияет на first.
} finally {
  explorer.dispose();
}
```

Сокращённый вариант `collatzGraph(n, maxVertices)` создаёт изолированную конфигурацию и освобождает Scope после одного результата. Входное число — `number` (безопасное целое) либо `bigint`; внутри всегда `bigint`. `maxVertices` — положительное безопасное целое. JSON.stringify с bigint напрямую не работает: преобразуйте значения вершин и концов рёбер в строки при JSON-экспорте.

## Как Event и Store взаимодействуют

```text
  explore(start, maxVertices)
       │
       ├── Store<GraphState> = { vertices:[start], edges:[], processed:0, ... }
       └── emit Expand({runId, vertex:start})
                        │
                        ▼ Commit
            Handler ExpandVertex (inline/each)
                        │
              read(GraphState), event(Expand)
                        │
              discover collatz(n), n+1
                        │
              set(GraphState) + emit Expand(next queued vertex)
                        │
                        ▼ Commit
                  ... пока FIFO не пуста
                        │
                        ▼
             inline() возвращается, граф готов
```

Событие не является постоянным хранилищем аргумента: один `Event` содержит конкретный `vertex/runId` и после обработки исчезает. Накопленные вершины, рёбра и счётчики живут в Store. Эмитируется **ровно одно** следующее событие на Commit, поэтому один Handler не конкурирует сам с собой за один Store в рамках волны.

`storage: "reference"` применяется только к внутреннему Store, потому что **каждая** часть GraphState, включая массивы и записи рёбер, замораживается через Object.freeze и никогда не мутируется. `ctx.set()` заменяет всю неизменяемую версию State. Возвращаемые результаты стабильны после последующих вызовов.

## Рёбра и визуализация

После исправления запускающий файл **автоматически рисует граф и сохраняет его**.
Файлы создаются в папке `graphs/` от текущего рабочего каталога (обычно корень Nexus):

```powershell
npm run collatz-graph-demo -- 1 10
ii .\graphs\collatz-1-10.svg
```

После выполнения появятся:

- `graphs/collatz-1-10.dot` — исходная схема на Graphviz DOT;
- `graphs/collatz-1-10.svg` — готовое изображение; открывается в Edge, Chrome или Firefox **без сторонних программ**;
- `graphs/collatz-1-10.png` — создаётся дополнительно, если Graphviz установлен и доступна команда `dot`.

**Graphviz необязателен.** Если `dot` не найден, SVG строится встроенным
рендерером Nexus (раскладка по слоям BFS, все дуги и циклы отображаются).
Если установлен Graphviz, для графов не более 250 вершин используется более
качественная раскладка Graphviz и создаётся PNG. Для больших графов Graphviz
автоматически пропускается, чтобы не блокировать терминал при отрисовке;
SVG и DOT сохраняются в любом случае. SVG с тысячами вершин будет большим —
его удобно масштабировать в браузере, но для действительно крупных графов
понадобится интерактивный визуализатор.

Лиловые стрелки — переход Коллатца, бирюзовые — `n + 1`.
Простые вершины выделены двойным кругом. Направление рёбер и цикл
`1 → 4 → 2 → 1` сохранены.

```typescript
import { collatzGraph } from "./examples/collatz-graph";
import { collatzGraphToSvg } from "./examples/collatz-graph-svg";
import { saveCollatzGraphFiles } from "./examples/collatz-graph-files";

const graph = collatzGraph(1, 10);
const svg = collatzGraphToSvg(graph); // SVG-текст без файловых API
const files = saveCollatzGraphFiles(graph); // сохраняет DOT + SVG (+ PNG)
console.log(files.svg);
```

`collatzGraphToDot(graph)` по-прежнему возвращает DOT. Само ядро Nexus не
импортирует Node.js/Graphviz: чтение/запись файлов — отдельный код примера.

## Ограничения и честная оценка

- Из-за полного копирования массивов вершины/рёбра при каждом реактивном шаге время порядка **O(maxVertices²)**, пиковая память для одного состояния — порядка **O(maxVertices)** (не считая временных копий и накладных расходов Nexus). Это учебный интеграционный пример, **не алгоритм для миллионов вершин**.
- Для чисел меньше `2^64` простота проверяется детерминированным Miller–Rabin; для более крупных `bigint` используется точный, но потенциально крайне медленный перебор делителей. Ограничение числа вершин **не ограничивает сложность** проверки огромного простого числа.
- В примере цепочка полностью **синхронна** (`execution: "inline"`); поэтому слишком большие бюджеты блокируют JS-поток. Для `deferred` нужна иная функция ожидания (`submitAndWait`) и соответствующая обработка ошибок/отмены.
- Если одна из реакций завершилась ошибкой после Commit, часть уже опубликованных предыдущих состояний останется: Nexus не предоставляет глобальный откат цепочки. В таком случае функция бросит исключение, а прежний снимок результата может остаться доступным.
- Настоящий Frida Gadget не задействуется; Core проверяется в Node.js.

## Проверка `1 → 4` из PowerShell

В исправленном примере правило Коллатца применяется и к единице. Цикл
`1 → 4 → 2 → 1` не приводит к бесконечной обработке: каждая уникальная
вершина расширяется только один раз.

```powershell
npm run collatz-graph-demo -- 1 10
```

Результат: **10 вершин, 15 рёбер, 4 простые вершины**.
В списке рёбер присутствуют `1 → 4 (collatz)` и `1 → 2 (increment)`.
При лимите в 2 вершины включится только `1 → 4`, потому что Collatz-переход
рассматривается раньше `n + 1`.

Команда без аргументов `npm run collatz-graph-demo` сохраняет прежний
режим демонстрации нескольких запусков.
