# Правила разработки Nexus

1. **Начинайте с владельца изменяемого ресурса.** `state` владеет ревизиями/ячейками; `transactions` — preflight и атомарной публикацией; `reactions` — subscription/registration/conflict/wave; `scheduling` — очередями, causal waiters и таймерами; `lifecycle` — ownership/cleanup; `diagnostics` — ошибками. Не создавайте `core/runtime`, `misc`, `common` или `utils` как общее место.
2. Новая реализация хранится в принадлежащей ей папке. `src/core/index.ts` и `src/frida/index.ts` — совместимые публичные barrels. Core не импортирует Frida; Java и IL2CPP не импортируют друг друга; `managed` — Bridge-независимый общий протокол.
3. Для пересечения границы используйте *минимальный интерфейс* в `src/core/internal/ports.ts`, если он устраняет зависимость от конкретного класса. Нельзя заменять каждое поле отдельным DI-интерфейсом. Публичные `Dispatcher`, `Context`, `Scope`, `Store`, `Event`, `Registration` требуют сохранения identity.
4. Прежде чем добавить новый межобластной импорт, обновите `scripts/check-architecture.cjs` и объясните причину в `docs/ARCHITECTURE.md`. Type-only импорт также контролируется. Не скрывайте циклы под `import type`.
5. Добавьте документирующий JSDoc с назначением, контрактом результата/исключений и **побочными эффектами** (`@returns`, `@throws`, `@sideEffects`) для новых публичных методов и важных внутренних операций. Нельзя обещать отмену уже начатого async или rollback внешнего I/O.
6. Не меняйте `StateTable.snapshot`, конфликты, execution fairness, `delivery`, `before/after`, `sequence` и commit admission в структурном PR. Для этих изменений нужен отдельный RFC и differential test.
7. Выполните `npm run typecheck`, `npm run test:all`, `npm run check:architecture`. CI проверяет собранные `main`/`types`, baseline exports, отрицательные импорты и JS agent bundle. Реальные Frida испытания проводятся *отдельно* по [`scripts/e2e/README.md`](../scripts/e2e/README.md).
8. `npm ci` должен использовать закоммиченный `package-lock.json`; не обновляйте TypeScript по плавающему `^`. После изменения компилятора повторите весь набор. Отдельно отметьте, был ли доступ к npm registry и к физическому устройству.
9. Не удаляйте существующие тесты ради зелёного статуса. Новая ошибка bootstrap, initial Handler, Scope/dispose или Bridge exception требует регрессионного теста на минимальном воспроизведении.
